AI 캡스톤디자인 · 개인 프로젝트

Industrial Sim Capstone · 스마트 팩토리 물류 시뮬레이션

Gazebo와 ROS 2 위에서 컨베이어 공급, RGB-D 비전 인식, 로봇팔 Pick & Place, Nav2 AMR 운송을 하나의 공정 상태 머신으로 통합했습니다. 실물 장비 없이 공장 물류 사이클 전체를 처음부터 끝까지 재현합니다.

완료 ROS 2 · Gazebo Nav2 AMR 로봇팔 · 비전

00 / DEMO

시연 영상

01 / BACKGROUND

문제 배경

스마트 팩토리의 컨베이어, 로봇팔, 비전 시스템, 무인운반로봇(AMR)은 벤더와 제어 방식이 제각각입니다. 그래서 이들을 하나의 공정 흐름으로 묶어 검증하는 일 자체가 비싸고, 실물 장비 없이는 실험하기 어렵습니다.

  • 장비 없이는 검증 불가. 로봇팔·AMR·컨베이어를 모두 갖추기 전에는 전체 물류 공정을 확인할 방법이 없습니다.
  • 통합 시점의 숨은 오류. 장비 하나하나는 정상이어도 신호를 주고받는 타이밍이 어긋나면 전체 공정이 멈춥니다.
  • 예외 상황 재현의 위험. 장애물 회피, 위치 추정 실패, 배송 재시도는 실제 환경에서 반복 재현하기 위험하고 번거롭습니다.

이 프로젝트는 물리 시뮬레이터(Gazebo)와 ROS 2 표준 인터페이스만으로 공장 물류 사이클 전체를 재현하고, 같은 시드를 넣으면 평가자가 같은 결과를 반복해서 확인할 수 있게 만드는 것을 목표로 했습니다.

02 / SYSTEM

공정 흐름

  1. ① 컨베이어 공급

    시드 기반 생성기가 A(빨강 큐브)·B(초록 원기둥)·C(파랑 육각기둥)의 투입 순서를 재현 가능하게 만들고, 컨베이어는 물품이 픽업 지점에 오면 자동으로 멈춥니다.

  2. ② RGB-D 비전 인식

    OpenCV HSV 색상 분할과 깊이 이미지로 물품의 종류, 3차원 좌표, 신뢰도를 계산해 관제에 표시합니다. 컨베이어 정지는 Gazebo 논리 카메라가 주 신호, 비전이 보조 신호입니다.

  3. ③ 로봇팔 Pick & Place

    회전·승강 관절의 실측값으로 목표 도달을 판정하는 상태 머신이 흡착 → 상승 → 회전 → 하강 → 분리 → 복귀 순서로 물품을 클래스별 상자에 적재합니다.

  4. ④ Nav2 AMR 운송

    적재가 끝난 상자가 LiDAR·AMCL로 위치를 추정하고 Nav2로 출하 도크까지 주행합니다. 시간 초과, 정체, 도달 오차가 생기면 최대 2회 자동으로 재시도합니다.

전체 공정은 factory_manager가 각 장비의 완료 신호를 모아 IDLE → CONVEYOR_RUNNING → ITEM_READY → PICKING → BOX_READY → AMR_MOVING → DELIVERED 순서로 관리합니다. 배송이 끝나면 상자가 복귀하고 다음 배치가 자동으로 시작되어, 사용자 개입 없이 생산 사이클이 반복됩니다.

03 / IMPLEMENTATION

핵심 구현

  • AMCL 위치 추정. 각 상자의 360도 LiDAR와 휠 오도메트리를 AMCL에 연결했습니다. 초기 위치는 Gazebo가 알려 주는 기준 위치로 설정하고, 추정값이 기준 위치에서 크게 벗어나면 버립니다. 시뮬레이션에서만 쓸 수 있는 보조 장치라는 점은 아래 한계에 적었습니다.
  • 동적 장애물 회피 데모. 주행 경로 근처로 팔레트 장애물을 옮겨, Nav2가 LiDAR로 장애물을 인식하고 costmap을 갱신해 경로를 다시 계획하는 과정을 RViz2에서 보여 줍니다.
  • 브라우저 관제 대시보드. 외부 웹 프레임워크 없이 Python 표준 라이브러리(http.server)만으로 공정 상태, 비전 신뢰도, 상자별 적재·배송 상태, 도크 상태, 이벤트 로그를 실시간으로 보여 줍니다.
  • 재현성과 테스트. 원버튼 실행 스크립트(run-demo.sh)와 시드 고정으로 같은 시연을 반복할 수 있고, 6개 패키지에 pytest 단위 테스트 20개를 두었습니다.

04 / PROBLEM SOLVING

어려웠던 문제와 해결

  • 비전 인식과 컨베이어 정지 타이밍이 어긋남. 비전 인식 결과가 늦게 들어오면 물품이 픽업 지점을 지나쳐 로봇팔이 집지 못했습니다. 정지 신호를 Gazebo 논리 카메라(주 신호)와 RGB-D 비전(보조 신호)으로 이중화하고, 투입 순서상 다음에 와야 할 물품인지 확인한 뒤에만 멈추도록 해 픽업 위치 정지를 안정화했습니다.
  • 컨베이어 옆에서 출발하는 상자의 경로 문제. 초록 상자(B)는 컨베이어 바로 옆에서 출발해, Nav2가 장애물 주변으로 판단하는 영역 안에서 주행을 시작해야 했습니다. 먼저 그 영역 밖의 탈출 지점까지 직접 이동한 뒤 Nav2 경로점 주행을 시작하도록 바꾸고, 이 순서가 유지되는지 단위 테스트로 고정했습니다.

05 / RESULTS

실측 결과 (시드 42 · 1회 실행)

  • 배송 결과. 이 실행에서 A/B/C 3건 모두 지정된 출하 도크에 도착했습니다(실패 0건). 도착 판정 기준은 목표 지점 0.8 m 이내입니다.
  • 처리 시간. 적재 완료까지 118초, 전체 배송 완료까지 606초가 걸렸습니다. 운송 구간(약 488초)이 전체의 약 80%를 차지하는데, 상자 3대가 한 대씩 순서대로 이동하기 때문입니다.
  • 재시도. 실패 시 최대 2회 재시도하는 정책은 단위 테스트로 검증했고, 이 실행에서는 재시도가 발생하지 않았습니다. 동적 장애물 데모에서는 Nav2의 경로 재계획을 확인했습니다.
  • 비전 신뢰도(참고값). 50~60%입니다. 정답과 맞았는지를 뜻하는 분류 정확도가 아니라, 색 영역의 모양(볼록도)과 채도로 계산한 확신 점수입니다. 분류 정확도는 따로 측정하지 않았습니다.
  • 자동 테스트. 6개 패키지의 단위 테스트 20/20 통과

위 수치는 시드 42로 한 번 실행한 결과이며, 여러 시드로 반복한 통계는 아닙니다. 실행 환경의 성능에 따라 시간은 달라질 수 있습니다.

06 / LIMITATIONS

한계와 개선 방향

  • 시뮬레이터 정답 정보에 기댄 부분. 컨베이어 정지의 주 신호인 논리 카메라와 AMCL의 초기 위치 설정·이상값 판정은 Gazebo가 알려 주는 정답 정보를 씁니다. 실물에서는 쓸 수 없으므로, 비전과 센서만으로 같은 안정성을 내는 것이 실물 이전의 과제입니다.
  • 비전 결과와 적재 결정의 분리. 어떤 상자에 담을지는 시드로 생성한 투입 순서를 따르고, 비전 인식 결과는 관제 표시와 보조 정지 신호에만 쓰입니다. 비전의 분류 결과가 적재 위치를 직접 결정하도록 연결하고, HSV 색상 분할을 딥러닝 객체 인식(YOLO 등)으로 바꿔 분류 정확도를 측정하는 것이 다음 단계입니다.
  • 단일 실행 결과. 결과는 시드 하나로 한 번 실행한 값입니다. 여러 시드로 반복해 성공률과 처리 시간의 평균·편차를 내야 성능을 주장할 수 있습니다.
  • 순차 운송 병목. 상자가 한 대씩 이동해 운송이 전체 시간의 약 80%를 차지했습니다. 여러 대가 동시에 움직이면서 서로 길을 양보하고 각자 판단하는 문제는 이 프로젝트에서 풀지 못했고, 이후 Physical AI 프로젝트에서 강화학습과 멀티에이전트로 이어서 다루고 있습니다.
  • 실제 장비 연동. 실제 PLC, 카메라, 로봇팔 드라이버 연동은 범위 밖이지만, 표준 ROS 2 인터페이스로 설계해 확장할 수 있게 했습니다.
